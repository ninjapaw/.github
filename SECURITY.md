# Security Policy

Ninja Paws repositories are independent community and demo projects. They are not
Microsoft products or GitHub products unless a specific repository explicitly
says otherwise.

## Reporting a Vulnerability

Do not open a public issue for a suspected vulnerability.

Use the target repository's Security tab and private vulnerability reporting
process when available. If private reporting is not enabled, follow the contact
or reporting instructions in that repository's `README.md` or `SUPPORT.md`.

Include:

- The affected repository, component, branch, and version or commit.
- A clear description of the issue and potential impact.
- Minimal reproduction steps or proof-of-concept details.
- Suggested remediation, if known.

Do not include secrets, credentials, access tokens, tenant data, customer data,
private keys, or other sensitive information in public issues, discussions, pull
requests, screenshots, logs, or sample files.

## Safe Use

- Treat all demo code, scripts, infrastructure, queries, and generated reports as
  examples that require review before use.
- Run demos in authorized non-production environments unless the repository
  explicitly supports production use.
- Validate security recommendations and configuration changes against your own
  tenant, subscription, threat model, and official product documentation.
- Rotate any credential or token that may have been exposed.
